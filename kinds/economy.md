# 走法：经济和数值漏洞（economy）

**抓什么**：能无限刷的闭环、能重复领的一次性奖励、边界值出错、读档重摇、罚不抵赚、跳过该付的账。多数是算术题：数值表在手就能算出来。

**不扮演性格。** 组里配的画像（算账的、压榨的、反复读档的）只提醒你玩家会往哪边钻。

出处和依据：`{{KIT}}\method\调研_审查种类.md` 3.2。 来源列表在 `{{KIT}}\docs\references.md`（编号 K 开头）。

## 要读什么

价格、奖励、折扣、好感、声望这些数在哪：项目设置的 `dataTables`（有的话）点了名；没有就从数据文件和代码里自己找，把找到的表写在报告开头。

## 怎么走

1. 列**进项表**（一切让钱、货、声望、好感变多的办法）和**出项表**。每项写：数值、条件、能不能重复、有没有冷却。
2. 找**闭环**：一圈操作下来净赚吗？买入价低于回收价、折扣叠加后低于回收价、换来换去、白送以后拿回礼再卖。
3. 找**能重复领的一次性奖励**：奖励发了以后，标记是不是马上写、马上存？条件还能再满足吗？读档以后会再发吗？
4. 找**边界值**：0、负数、上限、取整、乘法叠加、数量为 0 的交易、库存变负、钱不够时的"赊"。
5. 找**读档重摇**：随机结果是在行动那一刻才摇的吗？存档外有没有记录让它对不上？
6. 找**罚不抵赚**：罚的比违规赚的少，玩家就永远违规。
7. 找**跳时间**：睡觉、关门、跳过一个回合，能不能跳过交租、还债、限时任务。

## 每步问什么

- 这一圈每次净赚多少？要多久？有没有上限？
- 这个值有没有被夹在合理范围里？
- 这是作者想给的回报，还是漏了？

## 定把握

- 表里的数字直接算得出的：【确定】。
- 基础价在宿主游戏那边、作品里看不到的：【可能】，写明缺哪个数。
- 靠抢时机的复制（两个操作之间状态没锁）：静态看不出能不能真的做到，【可能】，写"这两步之间没有锁"。
- 设计好的回报（熟客折扣）不是 bug：写清数字，放进「要{{OWNER}}定」。严重度别写死，让{{OWNER}}排。

## 报告里多写什么

闭环写成**算式**（例："买 30，卖 35，每圈净 5，没有上限，一回合能做 N 圈"）。开头放进项表和出项表。
