# 走法：认知走查（walkthrough）

**抓什么**：新手做一件事时卡在哪一步：不知道要做、找不到怎么做、认不出那个按钮就是要点的、做完没有反馈或反馈说的和实际不一样。

这是"第一次玩的人"这个画像的固定格式版：每一步问同样的四问，所以两次审查的结果能比。

出处和依据：`{{KIT}}\method\调研_审查种类.md` 3.5（认知走查是可用性评审里的老方法）。 来源列表在 `{{KIT}}\docs\references.md`（编号 K 开头）。

## 怎么走

1. 选 3–5 件**新手一定要做的事**。项目设置有 `newPlayerTasks` 的用它；没有就自己选（第一次完成一个回合、第一次用作品加的东西、第一次接到一个请求、第一次被罚），写在报告开头。
2. 从代码、数据和说明文档写出每件事的**正确操作顺序**，一步一行。
3. 每一步问下面四问。任何一问答"否"，写一条问题。

## 每步问的四问

1. 玩家此刻**想**做这一步吗？目标从哪来：有哪句文本、哪个界面告诉他？
2. 正确的操作**看得见**吗？按钮、选项在不在？有没有被条件藏起来？
3. 看见了，会把它和目标**连上**吗？它的名字和前面提示里用的词一样吗？
4. 做完有**反馈**吗？反馈说的，和实际发生的一样吗？

每问只答"是 / 否 + 证据（文本的键、条件、`文件:行`）"，不写感想。

## 定把握

- 操作存不存在、被什么条件藏起来、有没有反馈文本、用词一不一致：【确定】。
- 显不显眼、看不看得清：读代码判不了，【可能】，写截图清单。
- 小心：你知道答案，会觉得"显然"。这个方法评的是最优路径，真人会乱撞。每一步都假设玩家只看过屏幕上出现过的字。

## 报告里多写什么

一张表：任务｜第几步｜哪一问不过｜证据｜把握。四问都过的步骤不用列，在「查过、没问题的」里写一行"任务 X 共 N 步，都过"。

可选：最后按"最伤新手"排一下前三条（头一段体验里最可能让人放弃的），每条必须挂证据，没证据的不写。
