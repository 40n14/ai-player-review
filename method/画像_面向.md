# 画像面向表

用这张表找出画像库里空着或覆盖较薄的格子，决定往哪补画像。格子的多少只反映库里写了多少种查法，不能用来估计有多少真人这样玩。

## 二、原来空着或覆盖较薄的格子

| 空或薄的格子 | 现有做法漏掉的动作 | 补上的画像 |
|---|---|---|
| 固定朋友一起连玩 | 以同一队报名、取消、回大厅、再排。查谁被留在原房间，谁被拆队 | 89 |
| 不用语音的陌生队友 | 发标记、让队友确认，再检查静音以后这条联系还在不在 | 90 |
| 错开上线的伙伴 | 甲保存退出，乙独自接手，甲回来看乙留下的变化 | 91 |
| 游客变正式账号 | 已有试玩进度时再绑定。外部账号已被用过时，取消并回到原档 | 92 |
| 玩家自己收起公开记录 | 改可见范围，按功能承诺对照作者、好友、陌生人的入口，再读到旧缓存的地方 | 93 |
| 第一次玩时避开剧透 | 用未见、刚见、换档三种进度打开同一帮助页、图鉴或成就页 | 94 |
| 使用资格到期再恢复 | 同一个号在资格有效、到期、恢复三次读同一份档 | 95 |

| 没有长按或组合键可用 | 53 已经沿必经步骤找单次操作。只有在作品明确支持开关扫描时，才有另一套焦点顺序可查 | 53（补充走法） |

上轮不收泛泛的社交、聊天和公会画像，因为得靠真人互动。89–91 限在作品能写明的组队、消息和存档动作。90 查玩家之间一发一收，作品自己的音效提示仍走无障碍清单。98 按账号实际给出的权限走，同年龄的账号也可能设置不同。上轮不收的手感、放松、画面音乐等，本轮也没有找到可以单列的只读动作。
