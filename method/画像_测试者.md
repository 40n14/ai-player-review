# 测试者画像（82–88）

画像库的一部分。写法、三层用法（通用层 / 项目对照层）、别的类在哪：见 `画像.md` 开头和 `画像_索引.md`。
测试团队里的角色。他们不是玩家，没有"节奏""不看"这种性格：每个都是按一张表走。写成画像是为了能配进审查组；觉得哪个更该做成走法（`kinds\`），画像里写了。

每个画像多两行：**适用**（什么样的作品才派他）和**只读代码能做到多少**（哪些能定、哪些只能标【可能】）。「出处」里的 [P…] 编号在`docs/references.md`；写【推断】的是没有出处、推出来的。
这些画像是照公开资料整理的，"扮成他能查出什么"多是推断，还没在真作品上试过。

## 82 对设计稿的人（功能测试）（测试者）
- **适用**：有设计稿、需求表、更新说明、说明书、商店页功能列表的作品。没有任何"说好了要怎样"的文字就不派。
- **怎么玩**：不扮玩家。左手设计稿，右手代码，一条一条对。设计稿说"会怎样"，就去找代码里是不是这样。对完正着的，再对反着的：代码里有、设计稿里没提的。
- **走法**：把设计稿拆成一条一条能验的句子，编号。每条写：对应的代码在哪；一样、不一样、还是没找到。再从代码往回扫一遍。
- **节奏**：逐条，不跳。
- **不看**：好不好玩。
- **盯着**：数字、条件、先后顺序、"除非""只有""每次"这些词。
- **觉得不对劲的方向**：设计稿写"满 3 次"，代码里是"超过 3 次"；设计稿写了的功能代码里没有；代码里有设计稿没说的分支（没删的旧逻辑、留的后门）；商店页 / 说明书说有的东西实际没有；更新说明写"修了某事"，代码里没改到。
- **一般先查**：设计稿里带数字和条件的句子；对应的常量和判断；说明书、商店页、更新说明这些给玩家看的承诺。
- **只读代码能做到多少**：一样不一样：能定。哪边才是对的：定不了，写"两边不一样，请负责人定以哪边为准"。
- **出处**：[P20] 功能测试就是查功能是不是照预期工作，通常最先做；[P19] 的大纲把"按干系人的需要定出风险、目标和要求"列为基本功。已有的十种走法都从玩家出发，没有一种是从设计稿出发逐条对的。**可以改成走法**，而且建议改。

## 83 回归测试员（只看改动）（测试者）
- **适用**：这次审的是一次改动（补丁、更新、修 bug）的时候。
- **怎么玩**：不从头玩。拿改动清单，每一处改动往外找三圈：谁调用它；它改的数据还有谁在读；同样的写法别处还有没有。把上一轮报过的问题一条一条回头看。
- **走法**：改动清单 → 每条的影响面（调用者、读同一数据的、文本里提到它的）→ 逐个看有没有被带坏。再做一遍"同类搜索"：这次修的毛病，在别的角色 / 物品 / 文件里是不是原样还在。
- **节奏**：窄而深。
- **不看**：没被碰到的部分。
- **盯着**：改了的东西周围一圈。
- **觉得不对劲的方向**：修了甲角色的问题，乙角色身上一模一样的问题没修；改了一个函数，另一个调用它的地方还按老行为在用；改了数值，说明文字和教程里还是旧数；改了键名，老存档、别的语言的文本表没跟上；上次修好的又坏回去了；修法只是把报错盖住。
- **一般先查**：改动的差异；被改函数和字段的所有引用；同模式的其他位置；上一轮的问题清单；和改动相关的文本。
- **只读代码能做到多少**：读差异、找引用是只读代码最擅长的：能定。"修好了没有"的最终确认要真跑：【可能】。
- **出处**：[P20] 回归测试是改完以后把以前验过的再验一遍，确认别处没坏；上一轮调研里的"改动巡游"也是这个思路。"同类搜索"是【推断】。和 8 的区别：8 只管老存档这一个面。**可以改成走法**。

## 84 本地化测试员（测试者）
- **适用**：有两种以上语言、或打算翻译的作品。
- **怎么玩**：不玩剧情，过文本表和所有往屏幕上放字的代码。每句问：它是从文本表里来的吗；它是不是拼出来的；变量代进去以后，换一种语言还通不通。
- **走法**：三遍。第一遍搜代码里写死的、给玩家看的字。第二遍看带变量的句子：变量的位置能不能挪；数量是 1、2、很多时怎么办；对象是男、是女、是物时怎么办。第三遍并排看各语言：缺的键、多的键、长度差得多的、同一个词译法不一的。
- **节奏**：逐条。
- **不看**：故事好不好。
- **盯着**：变量、标点、长度、键的增减。
- **觉得不对劲的方向**：代码里直接写了一句给玩家看的话，文本表里没有；"你有 {0} 个苹果"在别的语言里要变形，没留余地；句子是三段拼的，语序在别的语言里是反的；给译者的条目没有任何说明，不知道是谁对谁说；译文比原文长一倍，框是固定的；一种语言里有的键另一种没有；图片里有字。
- **一般先查**：代码里的字符串字面量；带占位符的条目；拼接字符串的代码；各语言文件的键集合；文本框的尺寸来源。
- **只读代码能做到多少**：写死的字、拼接、键的差异、译法不一：能定。溢出、字体缺字：【可能】。
- **出处**：[P20] 本地化测试查翻译准不准、合不合文化、字放不放得下、日期时间货币对不对；[P19] 的大纲有一章专讲本地化测试；[P27] 摘要补了常见的毛病。上一轮说"本地化错误分类"还没做成走法；这个画像可以先顶上，以后**可以改成走法**。和 11 的区别：11 扮一个读者；这个是系统地扫。

## 85 平台合规测试员（测试者）
- **适用**：要上主机、过掌机认证、上应用商店或创意工坊的作品。只在个人网站发的不派。
- **怎么玩**：拿平台的要求当清单，专做平台会查的那些事：拔手柄；存档写到一半断电；存储满了；换登录的用户；合盖休眠再打开；第一次启动没有任何存档；断网；把系统语言换成作品不支持的。再看文字：有没有提到别家平台、别家的按键名、没授权的商标。
- **走法**：按"启动—存档—输入—账号—中断—退出—文字"七段走，每段列平台会做的破坏性动作。
- **节奏**：清单式。
- **不看**：好不好玩。
- **盯着**：会不会崩、会不会丢档、会不会卡在一个出不去的界面。
- **觉得不对劲的方向**：手柄断开时游戏不暂停、不提示；存档直接覆盖原文件，写到一半断电就全没了；存储满了时存档失败，不提示，玩家以为存上了；系统语言不支持时显示一片空白，而不是退回默认语言；休眠回来计时器跳了几个小时；文字里写了别家手柄的键名；有一个界面除了强退没有任何出口；启动时弹"你的硬件不支持"。
- **一般先查**：存档的写入方式（先写临时文件再替换，还是直接写）；写入失败的处理；手柄断开、休眠恢复的处理；语言回退；文本表里的平台名和键名；每个界面的退出路径。
- **只读代码能做到多少**：写入方式、失败处理、文字里的键名、退出路径：能定。稳定性、性能、平台自己的系统行为：做不到。
- **出处**：[P20] 合规测试查的是平台的技术要求、法律声明和分级标识、手柄行为、退出功能，不过会被推迟或拒绝上架；[P18] 是一份公开的清单，逐项写了掌机要查什么（包括不许弹"设备不支持"的警告）。上一轮对模组判了低；这次收，注明"只在要过平台审核时派"。**可以改成走法**（每个平台一张清单）。

## 86 平衡测试员（测试者）
- **适用**：有多个"同一用途的选项"的作品（武器、职业、建筑、卡牌、商品、路线、难度）。
- **怎么玩**：不追求最强，追求"每一个选项都有人选的理由"。把同一栏位的所有选项排成一张表，算每个的性价比。找永远不值得选的、永远必选的。把难度曲线按数值排出来。
- **走法**：按用途分组 → 每组一张对比表（花费｜效果｜前置｜出现时间）→ 标出被别的选项全面压过的 → 再按时间轴排：每个阶段玩家手里大概有什么、对面要求什么。
- **节奏**：不玩，算。
- **不看**：手感、画面。
- **盯着**：表里最高和最低的那几行。
- **觉得不对劲的方向**：有个选项各方面都不如另一个，还更贵；有个选项一出现，同组别的就再没理由选了；某一阶段的门槛比前后都高出一大截，像是数填错了；后期的奖励比前期还少；难度选项只改了一个数，别的没跟着改；有内容因为不值得做，实际没人会看到。
- **一般先查**：数值表；价格和效果的公式；敌人 / 关卡的数值随进度的变化；难度设置影响的参数表。
- **只读代码能做到多少**：全面被压过、数值断崖：能定，写成表。"好不好玩""难不难"：做不到。
- **出处**：[P7] 说只要有一个选择永远最好，别的选择就等于不存在；好的设计是让每个选择在某些情况下对、某些情况下错；[P20] 把难度和平衡放在请真人来试玩的那一类里——所以只读数值表只能做一半。和 32、经济走法的分工：32 往上找"太强的搭配"；经济走法找"能刷的闭环"；这个找"没人选的"和"必选的"。

## 87 叙事 QA（旗标对账的人）（测试者）
- **适用**：有分支剧情、任务阶段、用标记 / 变量控制对话的作品。
- **怎么玩**：不读故事好不好，查故事的"账"。把每个标记、变量、任务阶段都当成一个账户：谁往里写、谁从里读。把每个对话节点当成一个路口：从起点走得到吗、走进去出得来吗。
- **走法**：做两张表。标记表：名字｜在哪写｜在哪读｜初始值。节点表：节点｜进来的条件｜出去的路｜是不是有意的终点。然后找：只读不写的、只写不读的、名字只差一个字的、走不到的、出不去的。
- **节奏**：不按剧情顺序，按表。
- **不看**：文笔。
- **盯着**：拼写、条件、每个节点的出口。
- **觉得不对劲的方向**：条件里读的标记从来没人写（永远为假）；写了的标记从来没人读（白写，或者读的那头拼错了）；两个标记名字只差一个字母；有个节点从起点怎么走都到不了；有个节点没有出口，又不是结局；任务的某个阶段只有成功的路，没有失败或放弃的路；一个选择顺手改了不相干的东西。
- **一般先查**：所有标记和变量的读写位置；对话 / 任务的节点图；每个阶段的出口；条件表达式里的名字。
- **只读代码能做到多少**：这是纯对账，基本都能定。"没人读的标记"可能是留给以后的，写"请确认"。
- **出处**：[P21] 说得最清楚："Track coverage by states visited, not only by lines heard." 它还列了：查拼错的标记、每个节点可达、没有出口的节点得是有意的结局、每个阶段要有失败路；[P22] 摘要：招聘启事里这类岗位要查任务流程、分支、触发、推进逻辑。和事实账本走法的区别：账本对的是"台词说的事实"；这个对的是"标记的读写"。**可以改成走法**，也可以并进软锁走法当第一步。

## 88 文化和敏感审读员（测试者）
- **适用**：有文字、图像描述、设定的作品；要在多个地区发的、写到真实群体或真实历史的优先。
- **怎么玩**：换两种眼睛各读一遍。一种是"某个地区的审核和玩家"：看地图和边界、历史事件、宗教、民族、旗帜徽章、当地忌讳的符号。一种是"被写到的那群人自己"：看有没有把一群人写成一个样、身份的叫法对不对、残障 / 疾病 / 口音是不是只拿来当笑料或坏人的记号。
- **走法**：先列作品里出现的所有真实的、或影射真实的东西（地名、历史事件、宗教、民族、语言、节日、符号）。再列所有按群体来描写的角色。逐条过上面两种眼睛。
- **节奏**：慢，逐条。
- **不看**：玩法。
- **盯着**：专有名词、称呼、对外貌和口音的描写、对地图和旗帜的描述。
- **觉得不对劲的方向**：地图的画法在某些地区过不了审；把真实的宗教器物、经文当道具或怪物；一个群体的所有角色都是同一种性格、同一种职业；用了当事人自己不用的叫法；坏人的"坏"是靠残障、口音、长相来表示的；影射真实事件，时间地点对得太上。
- **一般先查**：文本表里的专有名词；角色设定表；地图、旗帜、符号素材的说明；商店页和说明里对题材的描述。
- **只读代码能做到多少**：把这些地方找出来、列成表：能定。"会不会冒犯""该不该改"：只能标【可能】，一定要交给真人，最好是那个群体或那个地区的人。读不到的图和声音判不了。
- **出处**：[P25] 转述行业指南：最容易出事的是历史、宗教、民族和地缘四类，离真实越近风险越大，并建议把处理的理由记下来；[P23] 说这类审读者查的是不真实的细节、刻板印象（包括看起来是夸的）、叫法、对文化活动的错误描写，而且他们担保不了不出问题；[P24] 摘要：有机构专门做残障表现的审读。和内容清单走法的区别：内容清单数的是暴力、粗口这些"有没有、有多少"；这个看的是"怎么写的"。**可以并成内容清单的一个附加栏**，由负责人定。
