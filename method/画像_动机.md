# 动机画像（续）（45–52、94）

画像库的一部分。写法、三层用法（通用层 / 项目对照层）、别的类在哪：见 `画像.md` 开头和 `画像_索引.md`。
和 `画像.md` 里的 26–28 是一类：决定玩家**追什么**。不是一条线一条线地走：照每个画像的「走法」，先列一张表，再一项一项走。

每个画像多两行：**适用**（什么样的作品才派他）和**只读代码能做到多少**（哪些能定、哪些只能标【可能】）。「出处」里的 [P…] 编号在`docs/references.md`；写【推断】的是没有出处、推出来的。
这些画像是照公开资料整理的，"扮成他能查出什么"多是推断，还没在真作品上试过。

## 45 按人设选的人（角色扮演）（动机）
- **适用**：开局能选出身 / 职业 / 性格 / 阵营，或对话有多种态度可选的作品。
- **怎么玩**：开局定一个人设（例：胆小的学者；嘴硬心软的佣兵；只认钱的人），每个选择都按人设选，哪怕吃亏。没有合人设的选项就停下来记。留意作品替主角说的话、替主角下的心情。
- **走法**：定三个差得远的人设各走一遍。每个选择点记：有没有合人设的选项。再把所有"旁白替主角说话"的句子列出来对。
- **节奏**：慢，每个选项都念一遍。
- **不看**：哪个选项奖励多。
- **盯着**：作品认不认我的人设。
- **觉得不对劲的方向**：开局选的出身，后面再没人提过；选项只有"热心帮"和"恶狠狠拒绝"，没有平常地说不；旁白写"你愤怒地……"，可玩家选的是冷静；选了不识字的出身，照样读得了信；主角在过场里自己做了决定，和玩家一路的选择相反。
- **一般先查**：出身 / 职业的标记在哪些条件里被读到；每个选择点的选项覆盖几种态度；文本里第二人称带情绪、带动机的句子；过场里主角的台词。
- **只读代码能做到多少**：标记有没有被读、选项覆盖：能定。"口吻像不像"：【可能】。
- **出处**：[P2] 把"用自己设计的角色去经历故事、给角色编来历"列为一个动机；[P56] 摘要：生活模拟类的社区里有一群人自称"讲故事的"。上一轮把"沉浸叙事的人"并进了 17；这个不一样的地方是查"选项够不够"和"旁白越不越权"。

## 46 恋爱线的人（单推 / 全都要）（动机）
- **适用**：有可攻略角色、好感度、恋爱 / 结婚系统的作品。
- **怎么玩**：两种各走一遍。单推：只对一个人好，别人一概冷淡，礼物全给他。全都要：同时追所有人，每个人的好感都刷到顶，约会排在同一天。还有：表白被拒后接着送礼；在一起以后再去追别人；分手；对已有伴侣的角色示好。
- **走法**：列每个可攻略角色的门槛表（好感值｜必经事件｜锁线时间点｜和谁互斥）。再走"同时满足两条线"的每个时间点。
- **节奏**：围着人转，主线顺带。
- **不看**：和恋爱无关的系统。
- **盯着**：好感数字、特殊台词、称呼变没变。
- **觉得不对劲的方向**：单推到底，好感上限够不着门槛；锁线的时间点过了才知道；同时追两个人，两边都当没事；在一起以后，日常台词还是陌生人那套；被拒 / 分手以后，他还照常收礼、说情话；两个约会撞在同一天，只触发一个，另一个算爽约；称呼和代词在某些句子里没跟着变。
- **一般先查**：好感的来源总量对门槛；锁线条件；多条线同时成立时怎么处理；关系状态改了以后哪些台词池跟着换；带关系称呼的文本。
- **只读代码能做到多少**：门槛够不够、互斥、台词池：能定。"甜不甜"：做不到。
- **出处**：[P34] 摘要：这类游戏常有好感门槛和锁线点，存档位置选错就进不了线，玩家很依赖攻略；[P2] 的"关系"动机说的是和真人，搬到游戏角色身上是【推断】。碰到未成年角色出现在恋爱内容里，不往下走，直接报给内容清单。

## 47 不选默认的人（捏脸、自定义党）（动机）
- **适用**：有角色创建、外观 / 性别 / 称呼 / 声音 / 家园 / 界面自定义的作品。
- **怎么玩**：创建角色时每一项都不选默认：最后一个选项、最极端的滑块、和默认相反的性别和称呼、最高或最矮。在创建界面待一小时。中途去改外观、改称呼。把界面布局、配色也改掉。
- **走法**：列所有自定义项和取值。再列所有"假定了默认值"的地方（文本、过场、图标、存档缩略图）。
- **节奏**：开头极慢，后面正常。
- **不看**：默认推荐。
- **盯着**：我选的东西后面还算不算数。
- **觉得不对劲的方向**：文本里写死了"他""小伙子""你的黑发"；过场用的是默认形象；选了某个称呼，一半台词跟着变、一半没变；创建界面里计时器已经在走；中途改了外观，旧的头像、存档缩略图、别人对玩家的描述没更新。
- **一般先查**：带性别 / 外观词的文本有没有走变量；称呼变量覆盖了多少句；创建界面期间世界停没停；改外观的入口改了哪些状态。
- **只读代码能做到多少**：写死的词、变量覆盖率：能定。模型、穿模、好不好看：做不到。
- **出处**：[P2] 把"外观自定义"列为一个动机；[P1] 有一型玩家最看重能自己定制、能看着角色成长。和 31 的区别：31 是往输入框里打怪字；这个是在给定选项里选非默认的。

## 48 装饰和建造的人（动机）
- **适用**：能摆放、建造、布置的作品（家园、店面、基地、城市）。
- **怎么玩**：只为好看，不管功能。把装饰品堆满每一格；把必经的路堵死；把功能建筑拆了换花坛；东西摆在门口、楼梯上、角色站的位置；叠、转、贴边；摆到数量上限；摆完再全拆。
- **走法**：列所有可摆的东西和所有"世界需要空着"的位置（角色的站位、路径、刷新点、任务触发点）。每个位置试着占掉。
- **节奏**：慢，反复调。
- **不看**：效率、任务。
- **盯着**：摆得上摆不上；摆了以后别人有没有反应。
- **觉得不对劲的方向**：路堵死以后角色进不来，剧情停了；东西摆在事件要用的位置，事件不触发也不提示；拆掉正在被使用的建筑，里面的人 / 货没了；摆到上限时没提示，直接吞掉；装饰分数只看数量，同一样摆一百个就满分；搬家 / 扩建以后摆的全没了。
- **一般先查**：摆放的合法性检查；寻路失败时怎么办；事件对固定位置的依赖；拆除时对占用者的处理；数量上限；装饰评分的算法。
- **只读代码能做到多少**：检查有没有、上限、评分算法：能定。实际堵不堵得死：【可能】。
- **出处**：[P2]、[P1] 都有"定制 / 设计"这一动机；[P6] 里有一型玩家主要为了定制和装饰；[P56] 摘要：生活模拟类里"只盖房子的人"是公认的一群。

## 49 赌徒（刷开局、只信概率）（动机）
- **适用**：有随机结果的作品（抽取、掉落、暴击、随机事件、随机开局、赌博小游戏）。
- **怎么玩**：凡是带概率的都去碰。开局不满意就重开，重开五十次。同一个随机点反复试。只押最大的。相信写出来的概率，自己数抽了几次。攒着保底不用。用同一个种子再开一局，看是不是一样。
- **走法**：列所有随机点（在哪摇｜种子从哪来｜显示的概率｜代码里的概率｜有没有保底）。逐个对。
- **节奏**：反复重来。
- **不看**：稳妥的路。
- **盯着**：概率数字；保底计数；这次和上次一不一样。
- **觉得不对劲的方向**：界面写 10%，代码里是另一个数（或被别的修正悄悄改了）；保底计数在换池子 / 读档 / 跨天后清零了，没说；写着 0% 的还能出，写着 100% 的还会失败（取整、边界）；重开一下就能换开局，没有任何代价；同一个种子两次结果不一样（或说好随机的每次都一样）；连着几十次不中，没有任何兜底。
- **一般先查**：每个随机数的来源和种子；显示概率的文本从哪取数；修正项怎么叠；保底计数存在哪、什么时候清；比较用的是"小于"还是"小于等于"。
- **只读代码能做到多少**：显示和实际对不对得上、保底逻辑、边界：能定。"运气差不差"：做不到。
- **出处**：[P41] 把"开箱 / 赌博""可变奖励""控制错觉"列为手游里常见的手法；[P42] 摘要：东亚几地要求公开抽取概率，实际遵守得并不理想；[P6] 里有一型玩家就是追刺激。和 14 的区别：14 是读档重摇；这个盯的是"写的概率和算的概率"。

## 50 拆包的人（数据党 / 写维基的人）（动机）
- **适用**：所有作品（文件在玩家机器上的都算）。
- **怎么玩**：不玩，直接打开安装目录读数据文件和文本表。搜"test""debug""todo""未使用"。把内部名字、没用到的文本、没上线的内容都翻出来。拿文件里的数字去对界面上的说明。把发现写成维基。
- **走法**：按文件走，不按剧情走。每个文件问：这里有没有玩家不该看到的东西；这里的数和游戏里显示的一样吗。
- **节奏**：不玩游戏。
- **不看**：游戏本身。
- **盯着**：文件名、键名、注释、没人引用的条目。
- **觉得不对劲的方向**：文件名、键名、成就名直接剧透了结局；发布包里留着调试文本、作者的注释、内部笔记；留着没做完的内容，里面的设定和正式内容矛盾；说明文字里的数字和数据表里的不一样；同一样东西在两个文件里两个名字；包里带着不该带的东西（本机路径、账号、来路不明的素材）。
- **一般先查**：文本表里没被引用的键；数据文件里的注释和占位内容；键名和文件名的用词；发布包里有什么；说明文字里写死的数字。
- **只读代码能做到多少**：这是只读代码最顺手的一个画像，基本都能定。"算不算剧透""留着是不是故意"让负责人定。
- **出处**：[P46] 摘要：玩家拆文件能看到任何图片、文本、地点，但缺上下文；有的团队反感，有的干脆把秘密留给拆包的人找；[P3] 里有一型人专门欣赏规则和结构是怎么搭起来的。和 27 的区别：27 从玩的角度反查"到不了的文本"；这个查"文件本身露了什么"。

## 51 开着直播、录视频的人（动机）
- **适用**：所有作品；有联网、账号、授权音乐、剧透点的更要派。
- **怎么玩**：全程开着直播软件。屏幕上出现的一切都会被很多人看到并录下来。会停在菜单、读档界面、设置页上聊天。会把窗口标题、通知、报错弹窗一起录进去。
- **走法**：列"会上屏、又不是作者写的"文本：系统用户名、存档路径、账号、邮箱、房间码、好友名。再列"一眼就剧透"的界面：成就列表、读档界面的章节名、图鉴的空格名。
- **节奏**：慢，边玩边说话。
- **不看**：——
- **盯着**：屏幕上有没有不该给人看的。
- **觉得不对劲的方向**：默认角色名取的是电脑用户名；报错弹窗里带完整的本机路径；房间码 / 邀请码一直挂在屏幕上；读档界面的章节标题剧透；成就名和描述没隐藏，一打开全知道了；有授权音乐但没有关掉的选项；主播模式开了，只挡了一半。
- **一般先查**：所有读系统信息的地方（用户名、路径、机器名）；报错和日志上不上屏；成就 / 章节 / 图鉴名的显示条件；音乐来源表；主播模式开关管了哪些地方。
- **只读代码能做到多少**：系统信息上屏、剧透名、开关覆盖：能定。音乐版权：做不到（只能列"有没有标来源"）。观众观感：做不到。
- **出处**：[P47] 摘要：主播模式常做的几件事：换掉版权音乐、藏个人信息、藏名字；有的作品开关只管了一部分。上一轮判了低；这次只收"读代码能定"的那几条。

## 52 给作品做扩展的人（模组作者 / 民间翻译）（动机）
- **适用**：数据放在外部文件里，或者有模组 / 创意工坊 / 自定义内容 / 语言包入口的作品。作品本身是模组时，指"给这个模组再做附加包、翻译包的人"。
- **怎么玩**：照着作品的数据格式，自己加一个角色、一件物品、一种语言。故意写得不规范：少一个字段、多一个字段、编号撞车、名字很长、数量比作者想的多一倍。改完不看说明直接进游戏。
- **走法**：列作品从外部读的每一类文件。每类问：少字段、错类型、重复编号、条目数翻倍时，代码怎么办。再列代码里"写死了有几个"的地方。
- **节奏**：反复改文件、重进。
- **不看**：正常玩法。
- **盯着**：加的东西出不出来；坏了有没有提示。
- **觉得不对劲的方向**：代码里写死了"一共 8 个角色"，加第 9 个就越界；文本直接写在代码里，翻译包够不着；少一个字段就整个读不出来，也不说是哪一行；两个附加包编号相同，后一个悄悄盖掉前一个；加了新语言，字体里没有这些字；作品更新后格式变了，旧的附加包不报错，只是悄悄失效。
- **一般先查**：读外部文件的代码有没有校验和报错；写死的数量、写死的编号列表；代码里的硬编码文本；编号冲突的处理；格式有没有版本号。
- **只读代码能做到多少**：校验、写死的数、硬编码文本：能定。和某个具体附加包冲不冲：【可能】。
- **出处**：【推断】。旁证：[P25] 建议把符号、文本、引用做成容易改的，方便之后调整。和 12、补丁面走法的区别：那两个看"这个作品作为模组"会不会坏别人；这个看"别人往这个作品上加东西"会不会坏。

## 94 第一次玩想自己发现的人（动机）
- **适用**：有分段揭晓的剧情、谜题或解锁内容，且有可提前打开的帮助、日志、图鉴、成就等入口。
- **怎么玩**：第一遍不查外面的攻略。卡住时用游戏自己的提示，只要下一条线索。揭晓前先开一遍日志、图鉴、读档页或设置。揭晓后再开相同页面。作品有多个档、分支或角色时，回到另一个没走到这步的档再看一次。
- **走法**：选一件作品安排好揭晓时点的事。列“没见过—刚揭晓—换到另一个没见过的档”三种状态。逐栏看透露信息的是标题、描述、图，还是系统提示。若作品明确给了主动揭示的按钮，再分点和不点两支。
- **节奏**：愿意绕路找线索，确实卡住才要一点帮助。
- **不看**：攻略、全成就清单和明确标了“揭示答案”的内容。
- **盯着**：普通按钮给的是一步提示，还是把后面发生的事讲完了。
- **觉得不对劲的方向**：图鉴锁着，条目标题已经把身份说了。提示直接报答案，跳过了说好的逐层提示。第一档解锁了名字，第二档在本应保持未知的页面提前显示它。
- **一般先查**：揭晓标记什么时候写、帮助分几层、标题和详情用的条件是否一样、哪些记录全号共用。按作品说的公开范围判断全号记录是否显示得太早。
- **只读代码能做到多少**：能对明确写出的揭晓时点和文字显示条件。缩略图会泄露多少、真人能否从暗示猜出来，做不到。作品没定揭晓时点的，拿不准就标【可能】。
- **和谁不一样**：43 带着答案查能不能跳步。17 和 26 会多读、多开。25、10 和 51 已碰到某几处剧透。94 把同一个秘密沿不同入口和进度逐个比，能查出提示页或图鉴读错档、标题比详情先放出来的情况。
- **出处**：[P63] 说明平台成就可在解锁或主动揭示前隐藏标题与描述。跨入口和分存档的走法是【推断】。
