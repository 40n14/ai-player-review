# 详细用法

## AI 在对话里审查

请你的 AI 从 [AGENTS.md](../AGENTS.md) 开始。第一次照[安装说明](../for-ai/INSTALL.md)做。以后每轮照[审查步骤](../for-ai/PLAYBOOK.md)做。助手能读文件、跑命令就可以用。

## 命令行

在工具包根目录使用 `prk`。PowerShell 找不到时用 `.\prk.cmd`，也可以用 `python -I prk.py`。`-p <项目设置>` 可选项目，`--local <机器设置>` 可选机器设置。命令和输出字段见[命令参考](../for-ai/REFERENCE.md)。

- `prk guide --json` 从现有文件算下一步。`prk guide "问题"` 会另外用额度或钱。
- `prk check` 检查设置，`prk groups` 列审查组，`prk personas` 列画像，`prk suggest <游戏类型>` 给选组建议。
- `prk reports` 列轮次。`prk feedback` 看反馈，可用 `--save <文件>` 另存，或用 `--full` 看整份报告。
- `prk static` 单独跑静态表。`prk cite <轮次>` 单独核对引文。
- `prk ask` 显示怎么请自己的 AI 在对话里审查。直接执行 `prk` 可看终端菜单。

带问题的向导只读工具包说明。它收到问题、下一步提示和轮次的数字，项目设置路径用占位符表示。工具包不会把作品文件、项目名、报告内容或密钥传给这个向导。

用例子试命令，不花钱。请在工具包根目录执行。已有例子轮次时，`page` 默认选最新一轮。

```powershell
prk check -p examples\tea-stall\project.json
prk page -p examples\tea-stall\project.json --json
prk plan -p examples\tea-stall\project.json --split
prk prepare -p examples\tea-stall\project.json --groups A --json
prk fake -p examples\tea-stall\project.json --groups A,B --split --parallel 2
```

`plan` 只写任务文件，`prepare` 还跑静态表并建新轮次。`fake` 用假 runner 测排队、合并和花费表，里面的数字是假的。打开 `task_A_granny.md` 一类文件就能看到审查员收到的全部材料。

单跑茶摊静态表时，文字表应列 7 条可疑处，图片表应列出 3 张点得到的不到一半的图。

## 一轮怎么走

1. `prk prepare` 跑静态表，写任务文件，并在 `_prepared.json` 里列出顺序。默认用项目选好的组。只想听一类玩家怎么说，可用 `--who "15 + 18"`，也可用 `--kind` 选走法。
2. 在对话里按阶段做任务。同一阶段的任务可以同时做。任务里写明要读哪些材料、报告写在哪。
3. `prk page` 核对引文，写出一页纸 `review.md` 和离线页面 `review.html`。双击 HTML 就能看。可加 `--round` 指定轮次。
4. 在页面上选决定，点「复制给 AI」，贴回对话。AI 用 `prk decide --set` 记下决定，再刷新页面。下一轮先核上一轮要修的条目。

## 待修清单

说了「修」（`fix`）的条目会进 `待修清单.md` 或 `fix-list.md`，编号是 F1、F2 等。把单条交给自己的 AI，告诉它只修这一条。修完后核实、打勾，填写修复记录。这条路用项目自己的版本管理撤回。

后台也可以派 Claude Code 修一条。它会用额度或花钱，开跑前要负责人逐条同意。会备份出处指向的文件，可用 `prk fix F3 --undo` 恢复这些备份。只标状态用 `--done` 或 `--reopen`。详见[待修清单](../for-ai/REFERENCE.md#待修清单)。

## 审查种类

一个组由一种走法和几种画像组成。走法决定查什么，画像决定玩家怎么操作，项目设置决定这个游戏里去哪查。工具包有 98 个画像，见[画像索引](../method/画像_索引.md)。

| id | 名字 | 一句话 | 只读代码能做到多少 |
|---|---|---|---|
| `map` | 作品地图（审查前的准备） | 把作品读一遍，写出线、选择点、标记、东西、结局、数值、文本、牵连几张表 | 只写事实，每行带出处；后面的人用之前回原文件核 |
| `persona` | 画像走查 | 扮演一个具体的玩家，一步一步玩到结局 | 选择的后果、台词和状态：能定。手感：做不到 |
| `wants` | 想要的选项 | 每个选择点 × 每个画像：他最想做什么、选项里有吗；缺的设置、缺的反应 | 现在有哪些选项：能定。"他想不想要"：是推断，写理由 |
| `interaction` | 交互走法 | 模组的东西 × 宿主游戏的界面和系统，一格一格走 | 怎么取图、怎么认东西：能定。画面：要截图 |
| `softlock` | 软锁 / 卡死 | 列必经点，逐个问玩家能不能把它弄没 | 标记和条件写明的：能定 |
| `economy` | 经济和数值漏洞 | 进项表、出项表，找净赚的闭环和边界值 | 表里算得出的：能定。靠抢时机的：只能标可能 |
| `walkthrough` | 认知走查 | 新手要做的几件事，每步固定四问 | 有没有、藏没藏、用词一不一致：能定。显不显眼：要截图 |
| `tours` | 巡游包 | 中途退出、重复做、顺序对调、改设置，各穷举一遍 | 状态写入的顺序：能定 |
| `modsurface` | 模组补丁面和卸载 | 模组改了宿主的什么；卸载、宿主更新以后怎样 | 补丁方式、存档里写了什么：能定。和别的模组冲不冲：只能标可能 |
| `ledger` | 事实账本 | 先记账，再逐句对台词假定的事实 | 分段走：能定。整本凭印象：靠不住 |
| `a11y` | 无障碍清单 | 只靠颜色、只靠声音、限时、只说一次的信息 | 信息的来路：能定。实际效果：做不到 |
| `expand` | 内容拓展（审查后的可选环节） | 把"想要但没有的"写成内容提案和草稿；找哪类玩家没事可做 | 接得上现有的东西：能定。"玩家想要"：是推断 |
| `content` | 内容清单 | 可能要事先告诉玩家的内容，逐段打勾 | 文本：能定。图片和声音：没读到就不判 |

## 用到自己的项目

[安装说明](../for-ai/INSTALL.md)列了第一次要问的问题。也可以按[项目设置模板](../projects/_template.json)填。相对路径从项目设置所在文件夹算。

- `projectRoot` 是项目目录，`modSource` 指源码和数据，`reviewOutDir` 指报告写到哪。可以用 `neverRead` 划出禁读范围。
- `playUnit`、`playLoop` 写一轮有哪些界面。`reviewGroups` 和 `defaultGroups` 选走法和画像。
- `csv` 是两份文本表，自带的文字检查用。`personaOverlay` 是项目自己的画像对照，可照[茶摊的对照](../examples/tea-stall/画像对照.md)写。
- 本机 Python 或后台程序路径可按[机器设置样例](../local.example.json)填写。先用 `check` 验证，再用 `prepare` 查看生成的任务。
- 另有状态目录，用于保存上次的选择、演习和示范页。可用 `PLAYER_REVIEW_STATE` 指定。写不了时用系统临时目录下的 `PlayerReviewKit`。

## 语言

第一次装时，AI 会问用中文还是英文。在项目设置里填 `"language": "zh"` 或 `"language": "en"`。不填用中文。你明确选英文，或一直用英文和 AI 说话且没指定其他语言时，AI 会填 `en`。用 `prk check --json` 看选中了哪种。

报告、一页纸、离线页面、待修清单、决定记录、花费表和审查对话跟着项目语言走。项目语言也决定交付的默认文件名，比如英文用 `decisions.csv` 和 `fix-list.md`。命令的 JSON 字段名不变，普通提示可以是中文。两种文件名和决定词见[命令参考](../for-ai/REFERENCE.md#文件在哪)。

画像库、走法、代理说明和任务模板以中文为准。两套资料要改两遍，容易对不上。AI 可以读一套中文资料，再用你选的语言写交付。

## 后台跑的两种付法

| 付法 | 怎么付 |
|---|---|
| `sub` | 用本机 Claude Code 或 Codex 登录的会员额度 |
| `api` | 用机器设置里的密钥，按用量付费 |

先用 `prk plan` 看任务和估价。没跑过的模型可能估不了。负责人同意后，用 `prk run --pay sub --yes` 或把 `sub` 换成 `api`。结束后也用 `prk page` 出页面。只想后台跑一类玩家用 `quick`。

- `--groups A,B` 选组。`--split` 按 `characterSplits` 拆份。拆份且有多组时先合每组，再合整轮。
- `--parallel N` 限制同时跑几个。`--no-map` 跳过地图。`--map-dir` 用已有地图。
- `prk pay` 看或保存付法。`--pay` 只用于这次。`prk provider` 和 `prk model` 看或选服务商和型号。
- 后台可用 Claude Code、Codex CLI 或 Gemini CLI，取决于服务商。供安装和定价核对的出处见[参考文献](references.md)。工具包里的 Codex、Gemini 后台接法只用过假程序。用这两种时，禁读路径靠任务里的约定，机器设置里要明确接受。
- 每轮花费看该轮花费表，用 `prk reports --json` 的 `cost` 找。跨轮次看 `prk costs` 和 `花费记录.csv`（英文项目用 `cost-ledger.csv`）。工具包能记会员用掉的 token，查不到账号还剩多少额度。`prk costs --budget 20` 设每月 20 美元的提醒，`--budget 0` 取消提醒。

### 怎么接后台程序

| 程序 | 接法 |
|---|---|
| Claude Code | Anthropic、Anthropic 兼容接口、网关，或 Bedrock、Vertex、Foundry |
| Codex CLI | OpenAI API key 或本机的 ChatGPT 登录 |
| Gemini CLI | Gemini API key 或 Vertex AI |

每家服务商的地址、环境变量、可用模型和核对时间见 `api/providers.json`。本机设置可写 `claudeExe`、`codexExe` 或 `geminiExe`。用 `prk provider setup <名字>` 填密钥放哪，只填位置。模型选择的优先级依次为 `--model`、上次在 `prk model` 里记住的型号、机器设置的默认型号、后台程序自己的默认型号。

`prk pay guide sub` 或 `prk pay guide api` 可单独记向导的付法，用 `prk pay guide same` 恢复共用付法。脚本调用付费命令时需要明确付法和 `--yes`。会员模式不读取 API key。按次付费时，启动脚本默认隔离调用它的会话配置，避免把这次运行算到另一个账号上。

花费总账每个任务一行，重复记同一轮会去重。旧轮次用 `prk costs --rebuild` 重记。兼容服务商的实际价格可填机器设置的 `prices`，在总账里看「按价目表」。Claude Code 自报的折算金额与服务商账单可能不同。

## 预设：一类游戏一份现成的对照

画像分三层，审查员从前往后读，后面的为准：

1. **通用层**（`method\画像*.md`）：他是谁、图什么、怎么碰游戏。所有游戏一样，不带哪一类游戏的味道。
2. **预设**（`presets\<id>\画像对照.md`，可选）：这一类游戏里，每个画像具体怎么玩、先查哪。例：`shop-law` 是"开店 + 执法方"这一类。
3. **项目对照层**（项目设置的 `personaOverlay`）：这一个作品里对谁做什么、会说什么。

用法：项目设置里写 `"presets": ["shop-law"]`。`prk presets` 列出有哪些；页面的「玩家、走法、预设」里也能看。

加一个预设：在 `presets\` 下建一个文件夹，放 `preset.json`（`id`、`name`、`fits` 适合什么样的游戏、`personaOverlay` 对照文件名、`covers` 盖到哪些画像）和那份对照。对照里的小节标题用 `### 编号 名字`。预设写的是一类游戏，不写某一个作品的人物和文件。

## 加一种审查种类

1. 在 `kinds\` 写 `<id>.md`：什么时候用、要读什么、怎么走（一步一步）、每一步问什么、报告里多写什么。
2. 在 `kinds\kinds.json` 加一行：`id`、`name`、`file`、`what`、`needs`（要项目设置里有哪些字段）、`usesPersonas`、`splitScope`（按份拆分时范围怎么写）。
3. 在项目设置的 `reviewGroups` 里加一组，`kind` 写这个 id。

脚本不用改。审查员说明里的规矩、算不算问题、报告格式对所有种类都一样。

## 加一张静态表

照这个作品的数据格式写一个脚本，登记进项目设置的 `staticTables`（写法见 `static\run_all.py` 开头）。调用方式固定：

```
python -I <脚本> --project <项目设置> [--only a,b | --prefix a_,b_] <输出.md>
```

自带的图片表（`images`）不用写脚本：在项目设置的 `static.images.dirs` 里写上玩家要点、要拖的东西的图在哪，把 `images` 加进 `staticTables`。它只量面积；游戏按什么判定点中（像素 / 整格 / 矩形），审查员回代码查。

值得做成表的：每个角色的排期和条件、"上次 / 又"这类台词第一次见面会不会说、许诺的日子和实际间隔、模组的东西 × 宿主游戏会碰它的地方。静态表是线索，不是结论：审查员每条都回代码核对。

自带的表会跳过项目和机器设置的 `neverRead`。自定义脚本应复用 `static/projfile.py` 的 `machine_never_read`、`never_read_guard` 和 `walk_files`。`run_all.py` 会把本次选中的机器设置放进子进程的 `PLAYER_REVIEW_LOCAL`。

## 提示词是照什么写的

审查员和核对员的提示词照 `method\调研_提示词和准确度.md` 改过一轮。几条要紧的：

- **画像只管"手"，不管"脑"**。研究说给模型一个角色并不提高准确度，"装不懂"的角色还会拉低。所以画像只决定玩家做哪些操作、看哪些字；回代码查原因时，审查员用全部本事。画像的用处是让不同的审查员走不同的路。
- **有原文才算数**。每个结论带 `文件:行` 和那一行的原文；交报告前逐条重开出处核一遍；脚本再机械地核一次。
- **找和验分开**。审查员找；核对员看不到审查员的推理，自己走一遍。写得通顺的推理会把读的人也说服。
- **把握按证据分档**（确定 / 可能 / 设计），不让模型给自己打分：模型自己说的把握普遍偏高。
- **状态写在文件里**：覆盖表、候选、账本都进草稿文件，长任务被压缩上下文以后还能接着走。
- **不加的**：多代理辩论、"只有一组报就删"的投票、"资深专家"头衔、"务必仔细"之类的话。理由在那份调研的 3.7。

改提示词以前，先看 `eval\README.md`：用例子游戏的答案表量一量，再决定留不留。

## 还照某种格式的地方（照实说）

- 文字检查假设文本是两个 `键,文字` 的 csv，一个中文一个英文。别的语言对、别的格式要改 `review_text_checks.py` 或先转格式。
- 图片表只认 PNG，只量不透明的面积。审查员不看图：图画得对不对、看不看得清，查不了。
- API 模式的脚本是 Windows PowerShell 写的。静态脚本使用 Python 标准库。整套流程只在 Windows 上验证过。
- 画像的通用层是按"店、客人、剧情人物"这一类游戏写的。别的类型的游戏，玩法画像大多还用得上，善恶画像要看作品里有没有这些选择。

## 改工具包

- `.ps1` 只写 ASCII：Windows PowerShell 5.1 会把没有 BOM 的非 ASCII 字符读坏。中文放在 UTF-8 的 `.md` / `.json` 里。
- PowerShell 的变量名不分大小写。`player_review_api.ps1` 里 `$T` = texts.json、`$C` = 花费表的字，循环变量别用 `$t`、`$c`。
- `Start-Process` 传非 ASCII 路径会坏：任务文件和日志用英文名，报告名的中文在项目设置的 `reportNames` 里。
- 静态脚本只用标准库，带 `-I` 跑，不写 `__pycache__`。
- 用了别人的研究、数据、方法：来源写进[参考文献](references.md)（接着编号，写明读没读过原文），文档里用编号引、用自己的话转述。不在别的文件里另开来源列表。
- 新功能先想它属于哪一层：所有游戏都一样的进工具包；一个作品特有的进它的项目设置和对照层；一台电脑特有的进机器设置。工具包里不出现任何一个游戏的名字、路径、角色。
- 先看[设计](design.md)和[评测说明](../eval/README.md)。改完用茶摊例子、演习和假 runner 验证。

## 可选：本机页面

`prk ui` 会启动一个只监听本机地址的后台服务。页面仍可用来选项目、演习、开后台任务、看进度和花费、处理决定和待修清单。关掉窗口后，空闲的服务会自行停止。有后台任务时可回来继续看进度。「停下」会停止派发新任务，已经开跑的会继续。

旧页面的「开始一次检查」会先显示任务数和付法，再请你确认。「更多 → 命令行」列出相应的 `prk` 命令。由页面启动的任务有 `_运行记录.txt`，该轮的花费表记逐个任务的结果。页面因退出而关掉时，可以之后再开。想让空闲服务一直开着，启动时加 `--keep`。

这个页面保留现有功能，后续功能走 `prk page` 生成的离线页面。仓库不随附 exe。想用启动器，可以自己运行 `python -I launcher\build.py` 编译。启动器打不开时可看实际状态目录里的 `ui.log`。
